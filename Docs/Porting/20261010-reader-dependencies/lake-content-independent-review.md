## Earlier findings (resolved/deferred above)

1. **P1 — Deleted loader-alias capture still falls through to blank history creation.** `ReaderContentLoader.swift:618–629` checks `HistoryRecord.getOpenedRecord` (which excludes deleted records) and then only the primary key generated from `canonicalHistoryURL`. A historical record stored with `url = readerLoaderURL(for: articleURL)` has a different compound key. If that alias record has captured HTML and is deleted, opening the canonical article with `countsAsHistoryVisit: true` misses both checks, creates a new empty canonical record and leaves the captured alias tombstoned. `HistoryRecord.records(matching:in:)` already includes canonical and loader identities; the write-boundary resolver should consider those aliases including tombstones, with deterministic choice and explicit visit restoration. The new history regression covers only a canonical record. Add an alias-key tombstone runtime case that asserts preserved body/title/full-content flag, restoration, and no duplicate canonical record. Non-visit behavior should also assert no visit timestamp or deletion mutation.

2. **P2 — Authority-only promotion is discarded before mirror application.** `Feed Models.swift:1943–1964` constructs payloads only from persisted FeedEntry field changes. `containsFullContent` is carried only on the payload; FeedEntry exposes `rssContainsFullContent` through its Feed rather than as a persisted entry field. A feed initially classified as summary can populate an entry/bookmark with body bytes, then be reclassified to full-content while serving the same entry bytes and metadata. The next fetch considers the entry unchanged and returns no payload, so `applyFeedBody` never promotes the bookmark/history authority flag. The same problem affects a mirror created since the preceding identical feed fetch. The helper-level `testIdenticalFullBodyPromotesAuthorityOnce` proves the final helper but does not exercise this producer/filter/consumer boundary. Decouple mirror reconciliation from the entries needing persistence, retaining helper no-op suppression, or explicitly include authority/mirror reconciliation needs when producing payloads. Add an end-to-end same-entry-byte fetch after the feed authority switch and assert the captured mirror flag changes exactly once. This was a preexisting filtering limitation, newly relevant to the added provenance transport.

3. **P2 — Dedup remaps initial-scroll selection only, leaving ordinary selected occurrences orphaned.** `FeedView.swift:211–235` drops duplicate occurrences from displayed entries, and maps `initialScrollEntryID` to its representative. It continues passing the raw environment `contentSelection` into both lists. If a collection selects occurrence B and the full feed displays equivalent representative A with `initialScrollEntryID == nil`, or a refresh changes the preferred representative from A to B, the binding still contains the filtered-out compound key. `ReaderContentList` uses compound-key matching and native `List(selection:)`, so there is no displayed selected row; its selection callback cannot resolve that key. Collections correctly keep raw occurrence membership, but displayed selection needs a reversible mapped binding or selected-representative preservation without changing persisted identities. Add runtime selection-policy coverage separate from canonical deterministic sorting. The current canonical test checks representative choice only.
