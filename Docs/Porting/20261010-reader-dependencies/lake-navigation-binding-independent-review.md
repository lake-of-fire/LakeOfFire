## Conclusions

- Public navigation callback signatures remain unchanged. The original two-argument font helper remains and captures current identity before forwarding to the explicit captured-token overload. Main's CSS bodies, scheme selection, loader/blank/OS skips, font payload cache and argument payloads are retained.
- A captured nil token is not replaced by a fresh token inside the overload. Mounted callers with unavailable identity cannot inject fonts or proceed through callback checks. Unmounted callback native handling remains possible through `ownsReaderDocumentBinding(nil)`; JS evaluation itself throws cancellation rather than adopting a later mount.
- Committed callback uses the same token for font injection and pagination key evaluation; checks after each await prevent a replaced native binding from authorizing later native reader-mode changes. Pagination cancellation propagates rather than falling through as an ordinary logged JS error.
- Finished callback checks identity after font await and uses that same token for the final DOM state read. Both successful and ordinary-error completion paths recheck ownership before clearing loading state. Cancellation returns without clearing successor state.
- The helper's nil-token behavior is stricter than selected hotfix's unmounted evaluator fallback, but avoids the main evaluator's unbound timeout/error path and does not remove a valid mounted evaluation. No new source/API defect found from that difference.

## Test fixture and limitations

Four tests use actual ReaderModeViewModel and WebViewScriptCaller APIs with synthetic installed native bindings, unmanaged state and controlled async evaluation. They inspect mounted missing identity, retired explicit font token, same-URL binding replacement while font evaluation is suspended, and replacement while final finished-state evaluation is suspended. The final case begins successor pending state after replacement, so its assertion specifically checks that old completion cannot clear that newly admitted state. Gate releases and binding cleanup are present; no source-level API mismatch found.

This fixture qualifies neither actual WKWebView/frame execution nor runtime or Swift concurrency compilation. It tests native binding replacement; same-binding document-generation rollover is supported by the production token but not directly exercised here. The committed pagination callback has no corresponding runtime regression in these four methods. Font payload/cache paths were preserved by diff inspection, not executed. SwiftPM folder-based discovery includes this new file by path; an explicit Xcode project reference was absent at review, so native discovery remains unverified.

The token is captured at callback entry. This patch does not prove callback provenance before entry, nor durable writer admission. Native changes before the first await remain as in main. Later committed-callback `content.htmlToDisplay` and publication-date fallback suspensions still do not carry the new token checks in this patch. Dated `a9f1b522` covers that broader continuation behavior, but it is not claimed ported here. Rendering, mounted title and durable document fences remain outside this bounded review. Other workers' ongoing disjoint patches were not reviewed.
