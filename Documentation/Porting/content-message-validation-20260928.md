## Behavior port and destination preservation

The existing main/porting file still force-casts required page-supplied fields in
ReaderModeUnavailableMessage, ReadabilityParsedMessage, VideoStatusMessage and
PageMetadataUpdatedMessage. A dictionary alone is not a valid message: missing,
null or wrongly typed required fields can trap before consumers reject it.

Port the source's complete required-field checks. All existing public value names
and `init?(fromMessage:)` entry points stay in LakeOfFireReader. Complete value
implementations move into ReaderContentMessagePayloads.swift; the WebView adapters
call those same tested initializers rather than repeating parsing logic. The
NestedDOMRootSelector value moves with its existing initializer semantics.

Preserve Japanese/HTML content byte-for-byte as Swift String values, optional
selector/date/output defaults, absent captions behavior and per-dictionary invalid
caption rejection. This change does not introduce content-length caps or normalize
URLs/strings. A present URL string still uses Foundation's existing optional URL
parse; no new absolute-URL/scheme/origin policy is implied.

Adapt ReaderOnErrorMessage's optional finite document timestamp from the hotfix.
Absent or malformed diagnostic timestamps remain nil without suppressing the
error. Unlike the older source, a JSON boolean cannot become numeric provenance.
The timestamp is diagnostic data, not an admitted document capability.

Two refinements share the existing tested position-payload numeric/boolean helper
(now internal ReaderMessagePayloadValue): caption isAutoGenerated accepts actual
booleans rather than numeric 0/1, and diagnostics preserve numeric 0/1 timestamps.
The inspected YouTube caption producer emits a boolean comparison (`kind ===
'asr'`), so no producer format change is needed. Invalid caption dictionaries are
no longer printed; they can contain credential-bearing URLs. Other logging paths
are outside this change.

## Tests and reproduction

Run `bash Tools/test-content-message-payloads.sh -c debug` and `-c release`.
The fixture copies two complete production source files and complete tests without
rewriting implementations or replacing numeric conversion with a mock.

- 22 new Foundation cases exercise required-field rejection, all message shapes,
  Japanese/ruby text, optional defaults, selectors, captions, JSON type boundaries
  and diagnostic timestamp behavior.
- All 21 existing position/restore cases are retained unchanged in the fixture.
- Three additional macOS tests load only local HTML into a real WKWebView with a
  nonpersistent website data store, receive actual WKScriptMessage bodies, and
  execute these production decoders. Missing fields, Unicode, optional values and
  boolean/number endpoints cross the real JavaScript bridge. The tests neither
  contact external sites nor access the user's reader data.

Local Linux Swift 6.2.1 Debug and Release runs pass all 43 applicable cases, zero
failures. The three WebKit tests are macOS-only; their authored presence and local
syntax parsing are not execution evidence. Consult the PR's current workflow logs
for final macOS results. Repeated configurations are not additional unique tests.

## Remaining integration gates

The component fixture intentionally omits the SwiftUIWebView envelope type and
consumer/Realm graph. The unchanged public adapters are syntax-checked, not full
app-typechecked here. Even real WKWebView body delivery does not qualify native
receipt admission, frame registration, source ownership, delayed article writes,
SwiftUI presentation or full Reader initialization. Build/discover the owning
package and root Tuist targets, retain source/document fences and qualify the
composed app before advancing root pins. Existing loader/session/position/identity
work is retained, not replaced or claimed qualified by these tests.

No root gitlinks, schemas, historical primary keys, original books, package
requirements, signing, rollout flags or production CloudKit settings change.
